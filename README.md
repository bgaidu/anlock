# 儿童锁屏 · 答题解锁

一款面向**电视（Android TV）与平板**的儿童锁屏应用。按设定的"亮屏时长"自动锁屏，
孩子必须连续答对指定数量的题目（默认三年级水平、拼音 + 数学）才能解锁，家长可用 PIN 码随时快速解锁。

## 功能

- **开机自启**：设备开机后自动恢复计时（默认开启）
- **亮屏计时**：只按屏幕亮着的时间扣减额度，熄屏待机、关机都暂停，不冤枉
- **定时锁屏**：15/30/45/60/90/120 分钟六档可选（默认 30 分钟），到时自动锁屏
- **重启仍锁**：锁屏状态下关机重启，开机后立刻恢复锁屏
- **答题解锁**：累计答对 5/10/15 题（按家长设置的年级与科目出题）才能解锁（默认 5 题），答错不清零、换一道新题继续并扣 1 颗星（最低 0）；可选「填空题」让数学题自己输入答案，「自适应难度」按最近 20 题正确率在家长设定年级基础上 ±1 档（均可开关）
- **家长PIN**：家长可用 4 位 PIN 快速解锁（默认 1234，建议修改），防暴力尝试
- **防绕过**：改系统时间、杀后台、强行停止都无法绕过计时（见下方"计时与防绕过"）
- **紧急解锁**：忘记 PIN 时可用 adb 紧急文件恢复设备；「紧急重启解锁」（3 分钟内重启 3 次即解锁）默认关闭，需家长在设置页显式开启（见下方"紧急解锁"）
- **首次配置向导**：权限、电池白名单、PIN、10 秒真实试锁逐项检查，一次走完；老用户升级不会被强行弹窗，可随时在设置页重开
- **多科目分级题库**：家长可按孩子年级（学前~六年级，默认三年级）与已学科目（拼音/数学/英语/语文，默认拼音+数学，英语、语文默认关闭需手动勾选）配置出题难度（详见设置页"出题设置"）；**各科可单独设年级**，自适应难度只作用于仍跟随总年级的科目
- **数学题型扩充**：在四则运算、两步计算、分数/小数之外新增**单位换算、找规律、应用题**，全部为整数答案，兼容填空输入
- **每日总时长上限**：在单次时长之外再设每天的总上限，**平日/周末两套额度**（周末默认跟随平日），预设 60/90/120/180 分钟或自定义 1–720 分钟（默认关闭），家长 PIN 解锁可临时放行一次；锁屏页直接显示**今日剩余额度**（不限时 / 已用完 / 剩余分钟）
- **应用级限额**：按应用单独设每日时长（15/30/45/60/90/120 分钟、自定义、禁止使用或不限），**周末可单独设置或跟随平日**；超时只拦截该应用，桌面、电话和其他应用照常使用；家长可 PIN 加时 10 分钟或重置今日用量。依赖「使用情况访问」，无悬浮窗权限时用无障碍直接回桌面兜底
- **使用时段**：按周一~周日分别设置允许使用的时间段（默认 08:00–21:00，可自定义、支持跨零点），支持**工作日一次性统一设置**与**复制某天到其他天**；**常驻守护、不依赖"开始计时"**；时段外锁屏，时段恢复自动解锁，家长 PIN 可临时放行
- **使用记录与题库备份**：设置页可查看近 7 天使用时长，也可把题库导出为 JSON 备份或分享，再导入到别的设备；另支持**全量设置导出/导入**（额度、时段、出题、星星、统计、错题池；**不含 PIN**，导入后 PIN 为默认 1234）
- **错题本**：家长可查看全部错题（科目、题干、正确答案、复习日期），单条移除或确认后一键清空
- **护眼提醒**（默认关闭）：计时使用中每 15/20/30/45/60 分钟全屏提示 20 秒"看远处"，不影响计时；未授予悬浮窗权限时静默跳过
- **诊断日志**：设置页可查看/分享/复制/清空最近的关键事件日志，进程崩溃也会自动落盘，锁不住、声音没停等问题便于定位；分享诊断时自动附带家长操作记录
- **家长操作记录**：加时、PIN 放行、修改额度/应用限额、局域网操作等都会持久化到本机（最近 200 条），可在设置页查看、分享或清空，方便回看"今天到底是谁改了什么"
- **每周报告提醒**：每周日 20:00 发一条本地通知汇总本周使用时长与答题情况，点开即「近 7 天报告」；报告可一键分享给其他家长，也能在弹窗里开关提醒
- **通知栏快捷操作**：常驻通知提供「打开设置」与「家长加时」两个按钮；加时仍先进入 PIN 门禁，孩子点通知无法绕过
- **星星与错题复习**：锁屏答题答对得星星，每连对 5 题额外奖励，答错扣 1 颗星（最低 0）；家长可自定义"多少颗星换多少分钟"，兑换后下次解锁生效；答错的题会进入错题池，按 SM-2 间隔重复在后续解锁时优先复习
- **仅时段限制模式**：使用时段内可自由使用（不计时、不答题），时段外照常锁屏；家长可随时切回"时段内仍需答题换时长"
- **管控体检**：集中展示悬浮窗、无障碍、使用情况、电池白名单、通知、精确闹钟、设备所有者等拦截能力，并检测 **USB 调试 / 开发者选项 / 多用户模式**等绕过风险；未就绪项按风险排序并直接说明影响，可一键跳转修复，设备管理器被关闭时会主动通知家长
- **时间篡改检测**：通过墙钟与单调时钟对账识别改系统时间，检测到回退/跳跃时保留当日额度并提示家长确认
- **近 7 天报告**：内置柱状图展示 7 天使用时长，并汇总正确率、星星、最高连对、待复习错题与**使用最多的 5 个应用**
- **学习数据与每日目标**：设置页「学习数据与目标」按科目汇总近 7 天答题数与正确率，显示今日进度、连续达标与历史最长记录；每日目标可选 10/20/30 题或关闭（默认关闭），只做激励，不参与解锁也不改额度；近 7 天某科样本 ≥5 且正确率低于 80% 时给出一条薄弱科目建议；周报同步展示分科数据，学习数据与目标也可一键分享
- **按应用使用排行**：单独查看近 7 天各应用前台时长与占比，快速发现"时间都花在哪"；只读本机 UsageStats，不上传、不落盘
- **局域网家长面板**：同一 Wi-Fi 下用手机/电脑浏览器打开 `http://设备IP:8099/?t=口令` 即可查看状态、**孩子当前正在使用的应用**、当前应用的限额与今日用量、立即锁定、放行 15/30/60 分钟、加时或结束本轮、**给当前应用加时 10 分钟**；页面每 5 秒自动刷新状态与剩余时间，并展示**最近家长操作日志**（来源 IP / 命令 / 结果）；口令可在应用内重新生成
- **题库管理与判断题**：按科目/年级查看题库条数、来源（自定义/内置/兜底）与前 12 条预览，支持就地导入、导出、清除；可开启判断题（每 3 道穿插 1 道），错题加练也可单独开关

## 安装方法

### 电视（小米等 Android TV）

1. 如果之前安装过旧版，建议先卸载旧版
2. 将 `kidslock-release.apk` 复制到 U盘，插入电视 USB 口
3. 在电视上打开「高清播放器」或「文件管理」，点击 apk 安装
4. 安装前需在「设置 → 账号与安全」开启「允许安装未知来源应用」

### 平板（荣耀 / 华为等）

U盘或浏览器下载 apk 直接安装即可（应用同时声明了手机/平板启动器入口）。
安装后**必须**完成下面的权限设置，否则开机自启与防绕过会失效。

### adb 安装（电视/平板通用）

```bash
adb connect <设备IP>:5555
adb install kidslock-release.apk
```

## 安装后必做的权限设置

不同品牌的设置项名称略有差异，以下按荣耀/华为平板与小米电视归纳：

1. **允许自启动**：设置 → 应用 → 应用启动管理 → 本应用 → 手动管理，开启「允许自启动」+「允许后台活动」。不开则收不到开机广播，重启仍锁失效
2. **悬浮窗权限**：设置 → 应用 → 特殊访问权限 → 显示在其他应用上层 → 允许。这是锁屏防绕过的核心兜底，必须开启
3. **防杀后台**：多任务界面下拉应用卡片加锁，电池设置里对本应用关闭省电优化
4. **有权查看使用情况**（强烈建议）：设置 → 特殊访问权限 → 有权查看使用情况 → 允许。授予后"强行停止后继续使用"的时间也能在重启后补扣（见计时机制）；不授予则这段无法追账

## 使用流程

1. **打开应用**，进入设置页：选择观看时长、解锁题数、设置家长 PIN（建议第一时间改掉默认 1234）
2. **可选：设置总量与时段**：点「每日总时长上限」定一天总共能看多久（预设或自定义），点「使用时段限制」按周一到周日设允许使用的时间；开启后常驻守护，不依赖「开始计时」
3. **开始计时**：按「开始计时」，到时自动锁屏；也可按「立即锁定」马上锁
4. **答题解锁**：锁屏界面显示一个汉字和 4 个拼音选项，遥控器方向键选择、确认键提交（触屏直接点选）；答对累计进度，答错保留进度、换一道新题并扣 1 颗星（最低 0）；累计答对设定题数后自动解锁
5. **家长解锁**：锁屏界面选「家长解锁」，输入 4 位 PIN；输错 5 次锁定 30 秒
6. 解锁后可再次开始计时；锁屏状态下打开应用图标会被直接带回锁屏界面

## 紧急解锁（忘记 PIN 时）

按稳妥程度从高到低：

1. **输错被锁不是忘码**：PIN 连错 5 次只锁 30 秒，等 30 秒再试，想起密码随时可解
2. **adb 紧急文件（推荐，需电脑）**：锁屏状态下执行下面两条命令，开机即解锁并自动删除该文件：

   ```bash
   adb shell touch /sdcard/Android/data/com.kidslock.app/files/kidslock_emergency_unlock
   adb reboot
   ```

   文件在应用外部私有目录，应用免存储权限即可读取。老设备用文件管理器在同一目录新建同名空文件，效果相同。

3. **紧急重启解锁（默认关闭）**：设置页开启后，锁屏状态下 3 分钟内连续重启 3 次设备即解锁。⚠️ 孩子仅凭电源键即可完成，学会后可绕过锁屏，请自行权衡
4. **最后手段**：`adb shell pm clear com.kidslock.app` 清空应用数据——锁屏状态、PIN、年级科目全部归零（PIN 回默认 1234），设备解锁

## 计时与防绕过机制

### 亮屏计时

「观看时长」按**屏幕亮着的时间**消耗：

- 计时循环基于 `SystemClock.elapsedRealtime()`（开机单调时钟），**与系统时间无关**，改时钟无法延时
- 仅在屏幕亮起（`PowerManager.isInteractive()`）时递减，熄屏即暂停——熄屏待机、关机都不计时。孩子熄屏得不到任何好处：时间本来就只能亮屏消耗
- 每 5 秒原子持久化一组数据：剩余毫秒 + uptime / elapsed / 墙钟三枚时间戳

### 对账（防杀后台 / 强行停止）

服务意外死亡时，下次启动按两种情况追账：

- **同一轮开机内**（elapsedRealtime 未回退）：扣 `uptimeMillis()` 差值。uptime 在深度睡眠（熄屏挂起）时停走，所以"服务被杀但屏幕亮着"的时间照样扣回，熄屏期间死亡几乎不扣
- **经历过重启**（elapsedRealtime 回退）：用系统使用情况统计（UsageStats）统计上次时间戳以来**所有应用的前台使用总时长**并补扣——覆盖"强行停止后继续使用再重启"的漏洞。需授予"有权查看使用情况"权限，未授予时跳过补扣

已知的小偏差均偏保守方向（只多计不少计）：熄屏放音乐、AOD 常显等 CPU 不睡眠的场合会略微多计。

### 锁屏防绕过

- 锁屏时启用 HOME launcher alias（activity-alias 动态启停），按 HOME 回到锁屏界面（**并非所有厂商生效**，见下方注意）
- 全屏悬浮窗覆盖桌面，拦截遥控器/触摸操作；点击或 OK 键回到锁屏
- 守护服务每 800ms 检查锁屏是否在前台，不在则重新拉起（进程内静态引用判断，不依赖已受限的 `getRunningTasks`）
- 锁屏状态存 SharedPreferences，关机重启后由 BootReceiver 立刻恢复
- 返回键被锁屏界面屏蔽；锁屏期间打不开应用设置页

> 注意：HOME 劫持在部分厂商系统上失效。实测小米电视 4A（MIUI TV）连"选择默认桌面"弹窗都没有，按 HOME 后 MIUI 桌面直接取回前台，
> 是悬浮窗先盖住输入、守护服务 3~5 秒内拉回锁屏才没被绕过——也就是说这类设备上**悬浮窗权限是唯一起作用的拦截层**。
> 另有厂商在后台强杀服务导致守护失效。无论哪种，悬浮窗覆盖 + 家长 PIN 都是最后的防线，请确保悬浮窗权限已开启。
> 详见《部署手册》6.2 节。

## 技术参数

- 最低支持：Android 5.0 (API 21)
- 目标版本：Android 13 (API 33)
- 编译版本：API 34
- 架构：纯 Kotlin（已从 Java 全量迁移），无 native 依赖，电视/平板通用
- 界面：遥控器焦点操作 + 触屏点击均可，锁屏固定横屏

## 编译方法

> **环境准备（每台机器各做一次）**
> - **JDK 17**：AGP 8.2.0 / Gradle 8.5 需要 **JDK 17**；JDK 21/25 会导致构建失败，请勿使用系统里已有的其他 JDK。
> - **Android SDK**：**仓库不含 SDK**（`android-sdk/` 已被 `.gitignore` 排除，clone 下来不会有），需自行准备：`platforms/android-34`、`build-tools/34.0.0`、`platform-tools`，并接受 licenses。
> - **告诉 Gradle SDK 在哪**（二选一）：在 `local.properties` 写 `sdk.dir=<SDK路径>`（该文件已被忽略，不入库），或 `export ANDROID_HOME=<SDK路径>`。

```bash
# 一律用 Gradle Wrapper 构建：仓库已自带 gradlew / gradlew.bat / gradle-wrapper.jar，
# 无需在本机安装全局 Gradle（本机实测 which gradle 不存在），所以是 ./gradlew 而不是 gradle

# 方式一：构建 debug APK（自动使用 debug keystore 签名，可直接安装）
# 适合开发测试，但荣耀/华为等设备可能拒绝安装 debug 签名的 APK
export JAVA_HOME=<JDK17路径>
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew assembleDebug

# 方式二：构建 release APK（需要配置正式发布密钥库）
# 设置环境变量后，使用正式 keystore 签名，可在所有设备安装
export KEYSTORE_FILE=<你的.keystore路径>
```

## 本副本修复记录（相对上游）

### Bug 修复

1. **解锁指令永不执行**（2026-09-30）：`ACTION_UNLOCK` 原来写在已废弃的 `Service.onStart()` 里（Android 2.0 起系统不再回调），`unlockAndStop()` 是死代码——之前解锁全靠 watchdog 轮询发现状态变化才停服务。已移到 `onStartCommand()` 处理，解锁后悬浮窗立即移除、服务立即停止。
2. **计时依赖墙钟，改系统时间可绕过**（2026-09-30）：原实现用 `System.currentTimeMillis()` 算到期时间，把时间往后调即可无限续时。现改为**亮屏计时**（详见上文"计时与防绕过"）：`elapsedRealtime` 单调递减 + 熄屏暂停 + uptime 差值对账 + 跨重启 UsageStats 补扣，改时间、杀后台、强停重启三条路全部堵死。
3. **前台判断失真**（2026-09-30）：`getRunningTasks` 自 Android 5.1 起只返回调用者自己的任务，"锁屏是否在前台"的判断一直不准，导致 watchdog 反复做无效的 `startActivity`。改为 `LockScreenActivity` 用同进程静态引用上报自己的存活/前台状态。
4. **PIN 明文存储**（2026-09-30）：SharedPreferences 里直接存明文 PIN。改为随机盐 + SHA-256 哈希存储；旧版明文在首次校验成功时自动升级为哈希（按"长度非 64 位"识别明文，兼容旧版可能设置过的非数字 PIN）。
5. **PIN 存储损坏可导致永久锁死**（2026-09-30）：`sha256Hex()` 原实现 `catch (Exception) { return ""; }`——一旦哈希异常，空串被当成"已设置的 PIN"写入，之后任何输入都校验失败，孩子只能恢复出厂。现改为 `NoSuchAlgorithmException` 显式抛出（SHA-256 在 Android 上不会失败，但异常不该变成静默锁死）；`verifyPin()` 增加格式判定分支，长度非 64 且非 4 位数字的值视为"存储已损坏"直接拒绝匹配；`isPinUsable()` 供设置页判断能否走"重新设置PIN"恢复。
6. **设置页"立即解锁"按钮无 PIN 校验**（2026-09-30）：`MainActivity` 的解锁按钮直接 `setLocked(false)`。`onCreate` 的重定向挡住了锁屏状态下的进入，但边界情况可绕过——MainActivity 已打开期间若计时到期（`LockService.triggerLock()` 把 `isLocked` 置真），此时按一次"立即解锁"即完成绕过。已删除该按钮（解锁只应发生在锁屏界面，走认字或 PIN 两条路径）。
7. **`StandardCharsets.UTF_8` 拼写错误导致编译失败**（2026-09-30）：`sha256Hex()` 里 `StandardCharsets.UTF-8`（连字符）被 Java 解析为 `UTF` 减 `8`，编译报"找不到符号"。Java 常量名用下划线：`UTF_8`。已在 commit `b05b06c` 修正。
8. **旧默认值迁移反复执行，用户设置被静默重置**（2026-10-25）：`migrateLegacyDefaults()` 缺少一次性标志，每次构造 `PrefManager` 都会重跑——新版里家长选「五年级」或「只开拼音」后，下次打开应用/锁屏/重启就被重置回默认（三年级 / 拼音+数学）。已加 `legacy_defaults_migrated` 标志，迁移只在首次执行。
9. **开机"紧急窗口"死代码且判断方向写反**（2026-10-25）：`BootReceiver` 的紧急窗口分支依赖从未被写入的 `last_lock_time`，永不触发；且条件与注释相反（注释说"锁定后 5 分钟内不恢复"，代码是"锁定超过 5 分钟才解锁"），一旦补上写入调用就会变成"锁定超 5 分钟后重启即解锁"的绕过漏洞。已删除该分支及 `PrefManager` 中无调用方的 `getLastLockTime/setLastLockTime`。
10. **紧急解锁文件路径在所有系统上都读不到**（2026-10-25）：原检查 `/sdcard/kidslock_emergency_unlock`，但应用未声明存储权限——分区存储（Android 10+）与运行时权限（6~9）下均看不到该路径，此逃生通道实际从未生效。改为应用外部私有目录 `Android/data/com.kidslock.app/files/kidslock_emergency_unlock`（应用免权限可读，adb / 老设备文件管理器可写），并补充文档（见「紧急解锁」章节）。

- **答错不再清零**：锁屏答题答错时保留已答对进度，目标题数仍是家长设定的值（如 15 题），换一道新题继续；累计答对达到设定题数才解锁。此前答错会把进度清零，孩子容易挫败，也不利于把错题真正学会。
- **答错扣星**：每题答错扣 1 颗星，最低扣到 0；`RewardStore.removeStars()` 返回实际扣除数量，星星已为 0 时提示「星星已扣完」，不会出现负数。
- **进度与提示**：底部进度改为「已答对 X 题，还剩 Y 题即可解锁」，答错时 Y 保持不变；答错反馈明确显示正确答案、扣星结果与「换一道新题继续」。
- **纯逻辑与单测**：新增 `AnswerProgress`（答对累计、答错保持不变、解锁判定）与 5 项单测；新增 `RewardStoreTest` 3 项，覆盖加星、扣星下限与非正数扣星。

### 优化（1.0.1.26）

- **补齐通知刷新链路**：1.0.1.25 把正文改成分钟粒度并加了去重，但真机实测仍约每 31 秒刷新一次。原因是无障碍服务每 30 秒巡检时都会 `startService`，而 `onStartCommand` 里的 `startForeground` 会绕过去重直接重新提交通知。现在 `RecoveryAccessibilityService.startServiceSafely()` 在 `LockService.runningInstance != null` 时直接返回，`Revival.ensureRunning()` 也只在服务确实不在时才拉起，通知刷新重新回到「分钟文案变化才更新」。
- **实测结果**：见下文真机验证（1.0.1.26 复测后补充）。

### 优化（1.0.1.25）

- **常驻通知降频**：原来 `TimerManager.onTick` 每秒调用一次 `updateNotification()`，荣耀等系统会记录 `HwNotificationEntryObserver: reportNotification failed, more than 2000`。现在剩余时间改为分钟粒度文案（「剩余观看时间：约 N 分钟」，向上取整，不足 1 分钟显示「剩余观看时间不足 1 分钟」），并由 `NotificationRefreshGate` 对比正文：文本没变就跳过 `notify()`，只有跨分钟或锁定/解锁/熄屏暂停等状态切换时才真正刷新，通知更新频率降到约每分钟一次。

### 修复（1.0.1.21）

- **修复 Android 6 / MIUI TV 上输入家长 PIN 后崩溃（1.0.1.18 起的回归）**：设置页的「管控体检」与「今日已用」两处用 `TextView.append()` 拼接状态文字。Android 的 `append()` 会把 TextView 的 `BufferType` 从 `NORMAL` 升级为 `EDITABLE`，从而创建 `Editor` 并走 `Editor.drawHardwareAccelerated` 绘制路径；在 Android 6 的 MIUI TV 等定制 ROM 上该路径存在 `TextLine.handleText` → `Paint.getRunAdvance` 的 `IndexOutOfBoundsException`，家长一过 PIN 进入设置页、页面首次绘制时即崩溃。现改为用 `buildString` 拼完整字符串后一次性 `text = ...` 赋值，避免 BufferType 变化，并加注释说明不要再对只读 TextView 使用 `append()`。
- 影响范围：`MainActivity.updateStatus()` 中的 `btnHealth`、`tvDailyUsage`；其他 `append()` 调用均为 `StringBuilder` / `EditText`，不受影响。
