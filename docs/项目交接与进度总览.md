## 2. 项目概览

**KidsLock（儿童锁屏 · 答题解锁）**：一款面向 **Android TV / 平板** 的儿童锁屏应用。按家长设定的"亮屏时长"自动锁屏，孩子必须连续答对指定数量题目（按年级 + 科目出题）才能解锁；家长可用 4 位 PIN 随时解锁。

- **形态**：Android 应用（手机/平板/电视均可安装，同时声明 `LAUNCHER` 与 `LEANBACK_LAUNCHER`）
- **语言**：**纯 Kotlin 1.9.0**（Java 已全量迁移完成，`app/src` 下已无任何 `.java` 文件，单测也是 Kotlin）
- **最低/目标/编译**：minSdk 21 / targetSdk 33 / compileSdk 34
- **包名**：`com.kidslock.app`
- **版本**：versionCode 35 / versionName `1.0.1.32`
- **发布渠道**：GitHub Actions（`build.yml`，推送 `v*` 标签触发），密钥库经 `secrets.KEYSTORE_BASE64` 还原
- **无后端、无第三方在线服务**：完全离线运行，所有题目本地生成或从内置/导入题库读取

### 3.3 当前版本 / 进行中

**1.0.1.32 为维护版：选择题路径抽纯逻辑 + 单测，无用户可见行为变化，当前无进行中任务（下一版建议见 §3.4）。** 1.0.1.31 已修复平板填空题「提交」被软键盘遮挡（根因与验证见下）：

1. **根因**：`LockScreenActivity.hideSystemUI()` 在每次窗口获得焦点时都会补 `FLAG_LAYOUT_NO_LIMITS`。系统因此认为窗口允许超出屏幕，软键盘弹出时不执行 `adjustResize`——实测 `scrollRoot` 仍是 `2880×1840`，输入法 `touchableRegion` 从 `y=817` 起，`提交` 按钮 `(1125,850)-(1755,976)` 整块被键盘盖住；MagicOS 的输入法窗口 `frame` 上报为 `0×0`，系统也拿不到键盘高度，所以 `WindowInsets` 同样不可靠。
2. **修复**：`hideSystemUI()` 只保留 `FLAG_FULLSCREEN | FLAG_LAYOUT_IN_SCREEN`（不再有 `NO_LIMITS`）；`layoutFill` 由「输入框 / 提示 / 提交」竖排改为**输入框与「提交」并排一行**（`EditText` 360dp + `提交` 200dp），整行落在屏幕上半部分（实测 `y 609–735`），即使设备不响应 `adjustResize` 也不会被遮挡。回车提交、切回选择题收起键盘、`setupFillAutoScroll()` 兜底全部保留。
3. **真机验证**（荣耀 MagicPad 13 / GDI-W09 / Android 14）：debug 包 `com.kidslock.app.dbg`（与 Release 1.0.1.30 共存）验证——键盘弹出后输入框与「提交」完整可见；输入 `9` 判对、星星 5→6、进度 0/5→1/5；输错扣 1 星；输入法回车同样提交（1/5→2/5）。CI 产出 Release 1.0.1.31 装机复验——`版本 v1.0.1.31`，`12×6` 题输入 `72` 判对、星星 606→607、进度 0/15→1/15，下一道英语选择题键盘自动收起。
4. **电视侧行为不变**：电视仍只出四选项选择题，设置页不显示「填空」入口。
5. **1.0.1.32 维护**：新增纯逻辑 `OptionLayout`（显隐 / 第二行 / 四向焦点 / 「家长解锁」焦点）并替换掉 `LockScreenActivity.bindOptionFocus()` 里 90 行按 4 按钮写死的分支；`OptionLayoutTest` 8 项 + `MathSpecTest` 新增单位换算配对自检 1 项，单测总数来到 **26 个测试类 / 154 项**。焦点映射与原实现逐条对齐，用户可见行为不变（真机复验 4 选项与判断题布局、键盘交互均正常）。

上一版 **1.0.1.30**（上游）：修复应用限额弹窗 `FrameLayout.LayoutParams` 类型不匹配导致的闪退；`RecoveryAccessibilityService.isInputMethodPackage()` 让锁定/收窗与使用统计忽略输入法窗口；填空题增加 `scrollRoot` 自动滚动与回车提交兜底。再往前 **1.0.1.29** 修判断题只显示 2 个选项、按设备形态分流答题方式；**1.0.1.28** 为错题重练增强（掌握度、复习统计、加练占比、选项打乱）。

| PrefManager（SharedPreferences） | `PrefManager.kt` | 时长/题数/年级/科目、PIN 哈希、锁屏状态、计时对账时间戳、正确率统计、`legacy_defaults_migrated` 一次性迁移标志等 |

### 4.4 数据来源

| 来源 | 形式 | 用途 / 优先级 |
|---|---|---|
| **内置兜底字表** | `question/BuiltinPinyinBank.kt`（144 条，`BankEntry` 常量） | L3 强制回退，仅拼音；与 `assets/pinyin_5.json` 逐条一致（零漂移校验） |
| **assets 题库** | `app/src/main/assets/banks/{pinyin,english,ciyu}_{0..6}.json`（共 21 文件） | L1 同年级；L2 相邻年级回退；schema `{"entries":[{"k":..,"v":..}]}` |
| **家长自定义题库** | `getFilesDir()/custom_banks/<subject>_<grade>.json` | **L0 最高优先级**，仅支持拼音/英语/语文（数学为代码生成，不支持自定义） |
| **数学题** | `MathProvider.kt` + `MathSpec.kt` 代码生成 | 不来自题库文件，按年级随机生成算式 |
| **运行时缓存** | `BankRepository` 内 `ConcurrentHashMap` | 避免重复解析 assets |

> **校验任务**：`app/build.gradle` 的 `verifyQuestionBanks` 挂在 `preBuild`，构建前校验：拼音每级条目阈值（学前≥60、一~六≥100、`pinyin_5`=144）、英语/语文每级≥60、去重释义/拼音≥4、空字段拒绝，且 `pinyin_5.json` 与 `BuiltinPinyinBank.kt` 逐条比对。

## 5. 技术方案 / 架构设计

### 5.1 总体架构

```
UI 层
  MainActivity(设置/PIN门禁)  LockScreenActivity(锁屏答题)  QuestionPreviewActivity(预览)
        │                              │
        │                      DeviceProfile(设备判定: 电视=四选项 / 触屏=可填空)
        │                              │
服务/守护层
  LockService ── 拆分 ──► TimerManager(亮屏计时/对账/到期闹钟)
                       ├─ LockGuard(watchdog 拉回锁屏 + 无障碍自愈)
                       └─ LockOverlayManager(全屏悬浮窗覆盖)
  BootReceiver / AlarmReceiver / RecoveryAccessibilityService(无障碍守护)
        │
出题子系统 (question/)
  QuestionEngine ──调度──► QuestionProvider[]
        ├─ BankProvider(题库型): PinyinProvider / EnglishProvider / CituProvider
        ├─ MathProvider + MathSpec(代码生成型)
        ├─ DistractorSampler(干扰项采样)  RecentQuestionQueue(防重复)
        └─ QuestionUi(共用渲染器)
  BankRepository ── BankSource 责任链 ──► CustomBankSource(L0) → AssetBankSource(L1/L2) → BuiltinBankSource(L3)
        └─ CustomBankStore(自定义文件读写)
  Subject / Grade / BankEntry / Question(值对象)
        │
持久化
  PrefManager(SharedPreferences): 配置 / PIN(PBKDF2) / 计时对账 / 正确率 / 一次性迁移
```

### 5.2 核心模块说明

- **`TimerManager`**：基于 `SystemClock.elapsedRealtime()`（单调递增，与墙钟无关）的亮屏计时；每 1s 递减、每 5 tick 持久化；注册 `SCREEN_OFF/ON` 广播实现熄屏暂停；到期用 `AlarmManager.setExactAndAllowWhileIdle` 唤醒（被拒时降级 `setAndAllowWhileIdle`）。
- **`LockGuard`**：每 800ms 检查 `LockScreenActivity.isOnTop()`，不在前台则回调拉起；每 15s 检查无障碍守护是否启用，未启用则 `RecoveryAccessibilityService.trySelfEnable` 自愈。
- **`LockOverlayManager`**：`TYPE_APPLICATION_OVERLAY` 全屏 `FrameLayout`，拦截点击/OK/方向键，回退到锁屏；无悬浮窗权限时跳过（小米电视等靠它兜底）。
- **`QuestionEngine`**：`create()` 先按 `provider.isAvailable(grade)` 过滤科目，再以"有效科目集"算题量顺序表；全不可用则强制回退 `PinyinProvider`（守住"永不 null"契约）。`nextQuestion()` 经 `RecentQuestionQueue`（容量 10）防重复；`nextPreviewQuestion()` 不进队列。填空题开关再与 `DeviceProfile.hasTouchscreen()` 取与：无触摸屏设备一律按四选项出题。
- **`DeviceProfile`**：`isTelevision()` = `uiMode == TELEVISION` 或 `FEATURE_LEANBACK` 或 `android.hardware.type.television` 或**无触摸屏**（兜底不声明 leanback 的国产电视/盒子）；`hasTouchscreen()` 用 `FEATURE_TOUCHSCREEN`。填空能力挂在 `hasTouchscreen()` 上，避免电视端出现「只能遥控器点的打字题」。
- **`BankSource` 责任链**：`BankRepository` 按 `priority()` 升序（Custom=0 → Asset=1 → Builtin=3）遍历，首个 `usable()`（条目≥4）即返回；失败透明回退，绝不抛空。
- **`DistractorSampler`**：同池取 3 个不同值 + 正确项洗牌 = 4 选项，文本互异，绝不占位。
- **`PrefManager`**：PIN 用 **PBKDF2**（含随机盐，旧 SHA-256 明文自动升级）；计时对账三枚时间戳；累计正确率（total=0 时返回 -1）。

### 5.3 关键实现思路

1. **计时防绕过（核心难点）**：放弃墙钟，改用 `elapsedRealtime` 单调时钟 + 熄屏暂停 + uptime 差值对账 + 跨重启 `UsageStats` 补扣；三重守护（HOME alias / 悬浮窗 / 无障碍）互为兜底。改动此区域需极度谨慎。
2. **永不无题可出**：`BankSource` 三级兜底（自定义→本年级 assets→相邻年级→内置 144 条）+ 数学代码生成，保证 `QuestionEngine.nextQuestion()` 不可能返回 null。
3. **干扰项质量**：集中到 `DistractorSampler`，单测覆盖退化场景（题数 < 科目数）。
4. **预览隔离**：预览用独立引擎实例 + `nextPreviewQuestion()`，不污染正式防重复队列与正确率统计。
5. **默认值迁移**：`legacy_defaults_migrated` 一次性标志，避免每次启动重置家长设置（五年级/仅拼音 → 三年级/拼音+数学）。
6. **构建期资产校验**：`verifyQuestionBanks` 在 `preBuild` 强制校验题库完整性，作为冒烟测试。

### 6.5 交接必读（关键纪律）

1. **禁改清单（防绕过核心）**：`LockService` / `RecoveryAccessibilityService` / `BootReceiver` / `AlarmReceiver` 及 `PrefManager` 的计时对账逻辑，改动需评审；牵一发动全身。
2. **改默认值/规则要全链路同步**：PRD、`docs/设计-多科目分级题库.md`、`README.md`、代码注释中的年级/科目/题数默认值必须一致（曾出现多处残留旧值自相矛盾）。
3. **改 Kotlin 后必实跑 `assembleDebug --offline`**：新增集合类等极易漏 import，肉眼审不出（历史踩坑）。
4. **题库资产改动会触发 `verifyQuestionBanks`**：确保条目数/去重/空字段达标，且 `pinyin_5.json` 与 `BuiltinPinyinBank.kt` 一致。
5. **密钥库不在仓库**：release 签名经环境变量/CI Secret；切勿把 `.keystore` 提交入库。
6. **JDK 必须用 17**：系统若装了 21/25 会构建失败，用系统 JDK17（本机 Temurin 17.0.20.1）或 `JAVA_HOME` 显式指定。
7. **出题数量规则**：N>5 时单科上限 `⌈N/M⌉`（数学、英语各自 ≤ cap；拼音+语文合计 ≤ cap）；N=5 不设上限；上限永不突破。逻辑见 `QuestionEngine.buildSchedule` 与 `verify_schedule.py`（45 场景）。
8. **设备形态判断统一走 `DeviceProfile`**：不要在业务代码里直接判 `Build.MODEL` / 机型白名单。电视端新增交互前先确认遥控器可用（四向 + 确认），不要假设有软键盘；新增题型必须在「电视四选项」和「触屏填空」两条路径都想清楚，或明确只在触屏端提供。
9. **选项区改动必须走 `renderOptions()`**：2/3/4 选项的行显隐、按钮启用与焦点映射都由它统一处理。历史上「判断题显示 4 个选项」就是直接操作 `optionButtons` 造成的。
10. **调试包与已装正式包共存验证**：正式包 `com.kidslock.app` 无法 `pm disable-user`（`SecurityException`），且其无障碍服务会把外来窗口弹回。做法：临时在 `buildTypes.debug` 加 `applicationIdSuffix ".dbg"` 生成共存包 → 先用 PIN 解锁正式包（解锁后它不再覆盖外来窗口）→ 再启动调试包验证 → 验完删掉 suffix 并 `adb uninstall com.kidslock.app.dbg`。**该 suffix 不可提交**。

## 7. 在第三方工具中无缝继续开发的建议

- **直接 clone 即可构建**：远端已是干净可编译状态（本机已验证 `BUILD SUCCESSFUL`）。第三方工具只需提供 JDK17 + Android SDK 路径。
- **敏感/外部资源不要入库**：`.gitignore` 已排除 `android-sdk/`、`.workbuddy/`（本机已无该目录）、密钥库、`local.properties`。换机/交接时这些需**单独拷贝**：① 发布密钥库 ② `android-sdk/` ③ JDK17。
- **Gradle 缓存**：在 `~/.gradle`（约 500M+），离线构建需一并保留或首构建联网。
- **扩展方向**：新增题库来源（如远程题库 T13）只需实现 `BankSource` 接口并加入 `BankRepository` 的 sources 列表，无需改动引擎；多孩子（T14）从 `PrefManager` 维度隔离入手。
- **设备分流已落地**：答题界面按 `DeviceProfile` 分流——电视/盒子只出四选项选择题，平板/手机才提供填空题（软键盘 `EditText` + 「提交」）。新增题型或交互时两条路径都要考虑，或明确只在触屏端提供。
- **发布/推送网络**：本机直连 `github.com:443` 不通，git/curl 需 `git -c http.proxy=http://127.0.0.1:7890 …` 或 `curl --proxy http://127.0.0.1:7890`；远端名是 `anlock`。Release APK 只能由 CI 在 `v*` 标签上构建（本机无发布密钥库），产出 `app-universal-release.apk`。
- **文档基线**：需求/设计详见 `docs/PRD-多科目分级题库.md`、`docs/设计-多科目分级题库.md`、`docs/规划-后续迭代架构与任务分工.md`、`部署手册.md`；注意部分早期规划文档写于 Java 时代，类名已迁移为 `.kt`，以磁盘代码为准。
