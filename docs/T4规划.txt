## 一、Kotlin 迁移

### 1.1 策略：渐进式迁移，新旧共存

```
阶段 1（2 周）：基础设施
├── 添加 Kotlin 支持（build.gradle 引入 kotlin-stdlib + 插件）
├── 新代码全部用 Kotlin 写
├── 工具类优先迁移（BankEntry、Question、RecentQuestionQueue）
└── 保持 Java 可互操作（@JvmStatic、@JvmField、@JvmOverloads）

阶段 2（2 周）：核心逻辑
├── QuestionEngine → QuestionEngine.kt
├── PrefManager → PrefManager.kt（注意 SharedPreferences 的空安全）
└── BankRepository + BankSource 体系 → .kt

阶段 3（2 周）：UI 层
├── MainActivity → MainActivity.kt
├── LockScreenActivity → LockScreenActivity.kt
├── QuestionPreviewActivity → .kt
└── Adapter/自定义 View → .kt
```

## 二、远程题库

### 2.1 架构

```
家长设备 → HTTPS 请求 → 后端 API → 返回 JSON 字表
                                    ↓
                         RemoteBankSource（实现 BankSource）
                                    ↓
                         BankRepository L0/L0.5 优先级
```

### 2.2 后端 API 设计

```json
GET /api/v1/banks/{subject}/{grade}
Response:
{
  "version": "1.0.0",
  "subject": "pinyin",
  "grade": 3,
  "entries": [{"k": "脑", "v": "nǎo"}, ...],
  "checksum": "sha256:abc123..."
}
```

```json
GET /api/v1/banks/manifest
Response:
{
  "pinyin": { "0": { "version": "1.0", "url": "...", "sha256": "..." }, ... },
  "english": { ... },
  "ciyu": { ... }
}
```

### 2.3 客户端实现

```kotlin
class RemoteBankSource(
    private val context: Context,
    private val apiUrl: String = "https://api.kidslock.app"
) : BankSource {
    
    override fun priority() = 0  // 与 CustomBankSource 同级，可配置
    
    override fun load(subject: String, grade: Int): LoadResult? {
        // 1. 检查本地缓存（7 天有效）
        // 2. 缓存过期则请求 manifest 获取最新 URL
        // 3. 下载字表 JSON 并校验 SHA256
        // 4. 写入本地缓存
        // 5. 解析返回 LoadResult
    }
}
```

### 2.4 安全考虑

- **HTTPS 强制**：`network_security_config.xml` 禁止明文 HTTP
- **证书固定**：SSL Pinning 防止中间人攻击
- **完整性校验**：SHA256 校验下载内容
- **离线可用**：缓存命中时无网络也能出题

### 2.5 后端选型建议

| 方案 | 优点 | 缺点 |
|---|---|---|
| **Cloudflare Workers + R2** | 零服务器运维、全球 CDN、免费额度大 | 需学习 KV/R2 API |
| **Firebase Storage + Functions** | 生态成熟、认证集成 | 国内访问不稳定 |
| **自建 VPS** | 完全可控 | 运维成本高 |

## 四、Compose 预览界面

### 4.1 为什么只做预览

- 锁屏界面要求稳定性，Compose 渲染性能在低端 TV 上可能不如原生
- 预览界面是低频操作，Compose 开发效率高
- 风险隔离：预览崩溃不影响核心锁屏

### 4.2 实现

```kotlin
// QuestionPreviewActivity.kt 使用 Compose
class QuestionPreviewActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            PreviewScreen(engine = engine)
        }
    }
}

@Composable
fun PreviewScreen(engine: QuestionEngine) {
    var question by remember { mutableStateOf(engine.nextPreviewQuestion()) }
    
    Column(modifier = Modifier.fillMaxSize().padding(24.dp)) {
        Text(text = question.stem, fontSize = 56.sp)
        Text(text = question.hint, fontSize = 24.sp, color = Color.Gray)
        
        Spacer(Modifier.height(24.dp))
        
        question.options.chunked(2).forEach { row ->
            Row(modifier = Modifier.fillMaxWidth()) {
                row.forEach { option ->
                    Button(
                        onClick = { /* 高亮对错 */ },
                        modifier = Modifier.weight(1f).padding(8.dp)
                    ) {
                        Text(option)
                    }
                }
            }
        }
        
        Row {
            Button(onClick = { question = engine.nextPreviewQuestion() }) {
                Text("换一题")
            }
            Button(onClick = { finish() }) {
                Text("关闭")
            }
        }
    }
}
```
